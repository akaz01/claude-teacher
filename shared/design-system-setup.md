# 디자인 시스템 준비 (앱 슬라이드·디자인 캔버스로 만들 때 첫 단계)

이 플러그인을 쓰는 **모든 교사 계정에 같은 디자인 시스템 "teacher-kit 수업 디자인"** 을 두고, 덱과 학습지가 그것을 불러오게 한다. 그래서 누가 만들어도 같은 디자인이 나오고, 앱의 테마 메뉴에 "ink, amber" 같은 이름 붙은 색이 나타난다. 지금 판은 3이다(통합안: 명조 제목, 남색·노랑, 둥근 카드).

디자인 시스템의 내용은 모두 `teacher-kit-design-system.json` 한 파일에 들어 있다.
- `title`: "teacher-kit 수업 디자인"
- `version`: 판 번호(정수)
- `index`: 목차 파일(`project/design-system.json`) 내용
- `files`: 경로 → 내용. 경로는 디자인 시스템의 `project/` 아래 경로다(`tokens.json`, `README.md`, `components/…`).

앱 기능(결과물 도구)이 없으면 이 단계를 건너뛰고 `house-style.md`와 예시 코드로 만든다. 결과 모양은 같다.

## 1. 찾기

1. 계정의 디자인 시스템 목록을 본다(결과물 도구의 목록, 종류 "Design System").
2. 제목이 정확히 "teacher-kit 수업 디자인"인 것을 찾는다. 여러 개면 가장 최근 것을 쓴다.
3. 다른 디자인 시스템이 있거나 기본으로 표시돼 있어도, 교사가 그것을 쓰라고 말하지 않았으면 이것을 쓴다. 어떤 디자인 시스템을 쓸지 교사에게 묻지 않는다.
4. 이미 있으면 저장 여부를 묻지 않고 그대로 쓴다. 없을 때만 2절의 질문을 한다.

## 2. 없으면 만들기 (계정마다 처음 한 번)

0. **만들기 전에 교사에게 한 번 묻는다**: "선생님 계정에 수업 디자인을 저장해도 될까요?" 답을 받은 뒤에 만든다.
   - 거절하면 계정에 아무것도 저장하지 않는다. 디자인 시스템을 만들거나 불러오지 않고 `house-style.md`와 예시 코드의 기본 스타일로 덱·학습지를 만든다(결과 모양은 같다). 같은 대화에서 다시 묻지 않는다.
   - 질문 없이 진행해 달라고 했으면 계정에 저장하지 않고 기본 스타일로 만들고, 답변의 "기본값으로 정한 내용"에 적는다.
1. 디자인 시스템 종류(Design System)로 제목 "teacher-kit 수업 디자인"인 결과물을 하나 만든다.
2. `files`의 모든 항목을 **한 글자도 바꾸지 않고** `project/<경로>`에 쓴다. 디자인 시스템 기능의 안내대로 보낸다(한 번에 보낼 수 있는 수가 정해져 있으면 나눠 보낸다).
3. **맨 마지막 호출**에 `index`를 `project/design-system.json`으로 쓴다. `createdOnFiles.at`과 `lastChange.at`만 지금 시각(ISO-8601)으로 바꾼다.
4. 교사에게 한 줄로 알린다: "처음 한 번, 선생님 계정에 'teacher-kit 수업 디자인'을 만들었습니다. 앞으로 PPT와 학습지가 이 디자인으로 만들어집니다."
5. 디자인 시스템 페이지를 열거나 따로 설명하지 않는다. 바로 덱·학습지 만들기로 간다.

## 3. 있으면 판 확인

1. 그 디자인 시스템의 `project/tokens.json`을 읽어 `version`을 본다.
2. 묶음 파일의 `version`보다 작으면 새 판으로 바꾼다.
   - `project/design-system.json`의 `lastChange.via`가 `"teacher-kit"`이면(교사가 페이지에서 고치지 않았음): `files`를 다시 쓰고, 목차는 마지막에 다시 읽어 `lastChange`(by "Claude", via "teacher-kit", at 지금, note "판 n")만 고쳐 쓴다. 교사에게 한 줄: "디자인이 새 판(판 n)으로 바뀌었습니다."
   - 그 밖(교사가 고쳤음): 바꾸기 전에 묻는다. "새 디자인 판이 있습니다. 선생님이 고치신 디자인을 새 판으로 바꿀까요?" 바꾸라고 하면 위처럼 바꾸고, 아니면 지금 것을 쓴다. 질문 없이 진행할 때는 지금 것을 쓴다.
3. 같거나 크면 그대로 쓴다.

## 4. 불러오기

덱(앱 슬라이드)과 학습지(디자인 캔버스)를 만들 때 이 디자인 시스템을 **설치**한다. 설치 방법은 각 앱 기능의 안내(디자인 시스템 설치 절차)를 따르고, 아래만 정해 둔다.

- 폴더 이름(namespace)은 `teacher-kit`이다. 디자인 시스템의 `project/tokens.json`을 덱·캔버스의 `project/ds/teacher-kit/tokens.json`으로 복사하고, 목차의 `designSystems`에 기록을 더한다(`app-deck-example.md`의 예시 `deck.json`에서는 `designSystems`가 비어 있다. 설치하면서 앱 안내대로 채운다).
- 덱과 학습지의 마크업은 예시 코드(`app-deck-example.md`, `app-worksheet-example.md`)와 `house-style.md`를 그대로 따른다.
- **교사가 디자인 시스템의 색이나 글꼴을 고쳤으면** 고친 값을 쓴다. 덱의 `deck.css`와 학습지 마크업에서 같은 이름의 값을 바꾼다. 이름은 `house-style.md` 1절의 색 이름과 아래처럼 짝지어진다.

| house-style 이름 | 토큰 |
|---|---|
| 남색 | `ink` |
| 종이색 | `paper` |
| 옅은 하늘색 | `sky` |
| 흰색 | `page` |
| 노랑, 옅은 노랑 | `amber`, `amber-tint` |
| 파랑 | `blue` |
| 답 파랑 | `answer` |
| 흐린 글자 | `muted`, 어두운 바탕 `muted-on-dark`, 가장 옅은 글자 `faint` |
| 가는 선, 테두리 | `hair`, `line` |
| 학습지 자료·도움말 (황토, 테두리, 상자 바탕, 빈칸 바탕) | `gold`, `gold-line`, `cream`, `fill` |
| 시뮬레이션·그림 | `water`, `cold`, `hot`, `violet` |

- 글꼴은 토큰의 `serif`(Hahmlet)와 `sans`(Noto Sans KR)다. 교사가 글꼴을 바꿨으면 `deck.css`와 학습지의 같은 글꼴 목록을 바꾼다.

## 5. 안 될 때

디자인 시스템 만들기·읽기·설치가 거절되거나 실패하면 한 번만 다시 해 보고, 그래도 안 되면 디자인 시스템 없이 `house-style.md`와 예시 코드로 만든다. 결과 모양은 같으므로 작업을 멈추지 않는다. 답변 맨 아래에 "디자인 시스템을 불러오지 못해 기본 스타일로 만들었습니다" 한 줄만 적는다.
