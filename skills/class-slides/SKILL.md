# 수업용 PPT 제작

수업 흐름이 한눈에 보이도록 내용을 체계적으로 나눠 슬라이드로 만든다. 디자인은 고정 하우스 스타일(`references/house-style.md`)과 양식이 맡고, 이 스킬은 **내용 구성**에 집중한다. 학생이 답하는 장을 설명 사이사이에 둔다.

**교사에게 하는 안내·질문·설명은 모두 한국어로 쓴다.** (작업 중 도구 출력이 영어여도 답변은 한국어)
**답변 순서는 `references/answer-order.md`를 따른다.** (작업 중 설명 문장을 답변 맨 위에 쓰지 않는다)
**시작할 때 꼭 묻는다.** 첫 응답에서 1절 문구로 한 번만 묻는다. 지도안, 교과서 쪽 PDF, PPT 템플릿은 1번 질문으로 함께 요청하고 따로 다시 묻지 않는다. 질문 없이 진행할 때는 묻지 않는다.
**교과서 파일을 받으면 범위부터 묻는다.** 교과서 PDF가 첨부되면 "교과서 몇 쪽부터 몇 쪽까지 PPT로 만들까요?"라고 묻고, 답을 받은 뒤 시작한다. 교사가 이미 범위를 말했으면 묻지 않는다. 쪽 번호는 PDF 쪽수가 아니라 교과서에 인쇄된 쪽 번호로 맞춘다. 질문 없이 진행할 때는 첨부 파일 전체를 범위로 잡고 "기본값으로 정한 내용"에 적는다.

## 참고 자료

- `references/school-levels.md`: 학교급별 수업 특징과 차시 시간
- `references/curriculum-lookup.md`, `references/curriculum/`: 성취기준 찾는 절차와 데이터 (색인은 `references/curriculum/2022/INDEX.md`)
- `references/curriculum-transition.md`: 적용 교육과정 판별
- `references/teacher-profile.md`: `[교사 프로필]` 블록을 새로 만들거나 고칠 때의 절차
- `references/writing-style.md`: 4장 학생 대상 문체
- `scripts/make_deck.py`: **교사 템플릿이 없을 때 쓰는 기본 생성기.** 교과별 색으로 주기에 맞는 장(핵심어, 수업 안내, 설명, 확인, 연습과 답, 예제, 활동, 요약)을 만들고, 글자를 가로·세로 가운데로 맞춘다 (입력 형식은 스크립트 상단 설명)
- `scripts/make_pptx.py`: 테마 5종 PPT 생성기이자 **교사 템플릿(슬라이드 없는 .pptx) 채우기.** 설명 장의 핵심 띠(`key`)와 흐름·카드·그림 설명을 지원하고, 템플릿의 테마 색을 강조색으로 읽는다 (입력 형식은 스크립트 상단 설명). 공통 코드는 `make_pptx_base.py`, `make_pptx_color.py`, `make_pptx_diagrams.py`에 있다
- `scripts/fill_template.py`: 양식 복제기. 교사 양식의 슬라이드를 복제해 글·사진을 바꾸고 인포그래픽 도형·그림을 더한다 (입력 형식은 스크립트 상단 설명)
- `scripts/slide_check.py`: 저장 직전의 마지막 다듬기. `make_deck.py`와 `make_pptx.py`가 저절로 쓴다. 슬라이드 밖으로 나간 도형을 안으로 옮기고, 끝 줄에 몇 글자만 남거나 상자를 넘치는 글은 글자를 조금 줄여 없앤다
- `scripts/make_deck_check.py`: `make_deck.py`와 `make_pptx.py`가 쓰는 입력 검사. JSON 문법과 장 형식이 틀리면 몇 번째 장인지 한국어로 알리고, `--student` 선택을 읽는다
- `references/app-slides.md`: **교사 템플릿이 없고 클로드 앱의 슬라이드 기능이 있을 때(claude.ai) 쓰는 기본 방법.** 장 역할별 마크업, 클릭 공개, 실시간 시뮬레이션, 노트, 내려받기 안내
- `references/app-deck-example.md`: 앱 슬라이드 예시 코드. `deck.css`는 그대로 복사하고, 장은 마크업을 그대로 쓴 뒤 글만 바꾼다
- `references/house-style.md`: **모든 교사에게 같은 디자인**으로 나가게 하는 고정 스타일(색, 글꼴, 크기, 정렬, 하지 않는 것)
- `references/design-system-setup.md`: 앱 슬라이드로 만들 때 첫 단계. 교사 계정에 디자인 시스템 "teacher-kit 수업 디자인"이 없으면 만들고, 판이 낮으면 올리고, 덱에 불러온다
- `references/teacher-kit-design-system.json`: 그 디자인 시스템의 모든 파일을 담은 묶음 (고치지 않고 그대로 쓴다)
- `references/visual-design.md`: **형식 가이드**. 장 역할별 글 규칙, 핵심 포인트 띠, 인포그래픽 패턴, 사진·지도, 줄바꿈, 정렬, 확인 절차. pptx 생성기·양식 복제로 만들 때마다 따른다(앱 슬라이드는 `references/app-slides.md`와 `references/house-style.md`가 우선이다).
- `scripts/render_slides.ps1`, `scripts/check_wrap.ps1`: Windows + PowerPoint에서 장을 그림으로 내보내고 실제 줄바꿈을 센다 (확인용)

## 1. 요청하기

첫 응답은 아래 문구로 묻는다. `[교사 프로필]`에 있는 정보와 받은 자료로 알 수 있는 것은 목록에서 빼고 남은 항목의 번호를 다시 매긴다. 문구는 인용 표시 없이 쓰고, 문구에 다른 말을 더하지 않는다. 받은 자료를 다시 언급하는 문장도 넣지 않는다.

> 수업 PPT를 만들기 위해 알려 주세요.
> 1. 학년, 교과, 차시 (지도안, 교과서 쪽 PDF, PPT 템플릿이 있으면 함께 올려 주세요)
> 2. 슬라이드 수 (기본: 12장 안팎)
> 3. 인터넷 자료(영상·사진) 제안이 필요한가요?
> 4. 학생에게 나눠 줄 파일인가요? (그렇다면 정답과 노트를 뺀 학생용 사본을 함께 만듭니다)
>
> 질문 없이 바로 만들어 달라고 하시면 기본값으로 만들어 드립니다.

첫 응답은 이 문구의 첫 줄("수업 PPT를 만들기 위해 알려 주세요.")로 시작하고 마지막 줄로 끝낸다. 그 앞뒤에 인사, 작업 설명, 성취기준 설명을 붙이지 않는다. 이미 받은 자료는 1번 괄호에서 빼고, 셋 다 받았으면 괄호를 뺀다. 교사가 슬라이드 수, 인터넷 자료, 학생에게 나눠 줄 파일 여부를 이미 말했으면 그 항목을 빼고 번호를 다시 매긴다. 교과서 범위를 물어야 하면 그 질문을 목록 맨 앞에 둔다. 11~2월이고 교사가 학년도를 말하지 않았으면 `references/curriculum-transition.md` 판별 절차 1번의 학년도 질문을 그보다 앞, 목록 맨 앞에 둔다(교육과정이 두 학년도에 같아도 묻는다).

아래 값은 묻지 않고 기본값을 쓴다. 교사가 말하면 그 값을 쓰고, 기본값을 쓴 항목은 답변의 "기본값으로 정한 내용"에 적는다.

| 항목 | 기본값 |
|---|---|
| 지도안이 없을 때 | 성취기준과 교과서(받았으면)로 이번 차시에 학생이 꼭 해야 할 활동 하나를 정한다 |
| 함께 쓰는 학습지 | 없음. 자세한 내용도 화면과 노트에 둔다 |
| 학생이 답할 도구 | 손들기와 공책 |
| 슬라이드 수 | 12장 안팎 (2절) |
| 인터넷 자료 | 찾지 않는다 (인터넷 자료 질문에 필요하다고 답했을 때만 찾는다, 3절) |
| 학생용 사본 | 만들지 않는다 (교사용만). 4번 질문에 그렇다고 답하면 4절의 `--student`(앱 슬라이드는 `references/app-slides.md` 7절)로 학생용 사본을 함께 만든다 |

학습지를 함께 쓴다고 하면 자세한 내용을 학습지로 보낸다.

테마는 묻지 않는다. 템플릿이 없으면 클로드 앱의 슬라이드 기능으로 만들고 디자인은 누가 쓰든 `references/house-style.md` 그대로다(덱마다 새 색·글꼴을 정하지 않는다). 그 기능이 없으면 교과별 색으로 만든다(같은 교과면 누가 만들어도 같은 색이다. `references/house-style.md`의 예외 3). 교사가 먼저 테마를 말하면 `make_pptx.py`로 만든다: 기본 `basic`, 초등 `elem`, 이과 `sci`, 문과 `hum`, 고대비(칠판형) `board`.

**질문 없이 진행해 달라고 할 때.** 교사가 "질문하지 말고", "알아서 끝까지"처럼 바로 결과를 원하면 묻고 확인받는 단계를 건너뛴다. 이 경우에도 지어내지 않는다.
- 빠진 값은 이 스킬의 기본값(학교급 기본값 포함)으로 채운다. 핵심 수치도 같다.
- 답변 맨 위에 "기본값으로 정한 내용"을 목록으로 적는다.
- 확인이 필요한 사실은 문서에 `[확인 필요]`로 두고, 답변 맨 아래 "확인 필요" 목록에 모은다.

**성취기준.** 지도안이 있으면 지도안의 성취기준을 그대로 쓴다. 지도안이 없으면 묻지 않고 `references/curriculum-lookup.md` 절차로 이번 차시에 가장 가까운 성취기준을 찾아 학습 목표와 내용을 맞춘다.
- 코드와 문장은 기억으로 쓰지 않고 자료의 것을 그대로 쓴다. 슬라이드에는 넣지 않고 표지 장의 발표자 노트에 적는다.
- 답변의 구성표 위에 적용 교육과정과 쓴 성취기준을 한 줄로 적어 교사가 확인하게 한다.
- 적용 교육과정이 2015 개정이면 2022 개정 코드를 쓰지 않고 `[확인 필요]`로 둔다. 찾지 못했을 때도 같다.

## 2. 내용 구성 (가장 중요)

어떤 생성기를 쓰든, 기본 슬라이드 기능을 쓰든 이 절의 내용 규칙(주기, 장 역할, 노트)을 같게 지킨다. 다만 글자 정렬과 "핵심: …" 띠의 모양 규칙은 pptx 생성기와 양식 복제에만 적용한다. 앱 슬라이드는 `references/house-style.md`(제목·설명·핵심 줄·지시는 왼쪽 정렬, 핵심 줄은 `.key` 모양)가 우선이다. 장은 생성기 이름이 아니라 **역할**로 적었다. 역할과 입력 종류의 대응은 4절 표에 있다.

### 기본 흐름

**지도안이 있으면 지도안이 먼저다.** 도입–전개–정리 순서, 활동, 목표 문장, 발문을 그대로 따르고, 아래 뼈대는 그 안에서 확인·연습을 넣을 자리를 찾는 데만 쓴다. 지도안이 없으면 아래 뼈대로 만든다.

| 단계 | 장 |
|---|---|
| 도입 | 표지 → 학습 목표 **2개 이내** → 핵심어 → (동기 유발 또는 O·X로 생각 끌어내기) → 수업 안내 |
| 전개 | 주기 **2개** (내용이 많으면 3개까지) |
| 정리 | 요약 → (되돌아보기·더 나아가기) → (차시 예고) |

**주기 하나.** 소주제마다 주기를 하나 둔다.

1. 수업 안내: 주기 목록과 지금 위치 (주기가 2개 이상일 때). 첫 주기는 도입의 수업 안내 장이 겸한다. 그 장에 첫 주기를 지금 위치로 표시하고, 수업 안내 장을 연달아 두지 않는다
2. 설명 1~2장
3. 확인 1장 (앱 슬라이드는 같은 장에서 클릭하면 정답이 나타나므로 정답 장을 따로 두지 않는다)
4. (내용이 많으면 설명 1장 + 확인 1장을 한 번 더)
5. 연습 1장
6. 답 1장 (앱 슬라이드는 시뮬레이션으로 직접 확인하고 클릭하면 예시 답이 나타나게 할 수 있다)

- 연속 설명은 3장을 넘기지 않는다. 교사가 강의 중심 수업을 원하거나 지도안이 다르면 그대로 따르고 그 사실을 답변에 적는다.
- 토론, 실험, 모둠 산출처럼 활동이 긴 차시는 주기를 1개로 줄이고, 연습·답 대신 활동 이름 장 + 방법 장을 둘 수 있다. 줄였으면 답변에 밝힌다.
- 교사 전용 안내 장은 만들지 않는다. 교사 안내는 노트와 답변으로 준다.

**장 수 기본값은 12장 안팎이다.** 교사가 슬라이드 수를 말하지 않으면 12장 안팎으로 만들고, 주기 수는 아래 표를 따른다. 장 수는 정답 장까지 넣어 파일 전체로 센다(앱 슬라이드는 클릭하면 정답이 나타나므로 확인 문제의 정답 장이 없다).
- 상한은 14장이다. 넘으면 이 순서로 줄인다: 연습과 답은 마지막 주기에만 둔다 → 설명은 주기마다 1장으로 → 차시 예고는 요약 장의 노트로 옮긴다 → 새 용어가 2개 이하면 핵심어 장을 빼고 설명 장에서 풀이한다.
- 그래도 내용 때문에 넘거나(고등학교 주기 3개, 지도안이 정한 활동 수 등) 10장보다 모자라면 억지로 맞추지 않는다. 이때도 16장을 넘기지 않고, "기본값으로 정한 내용"의 장 수 줄에 장 수와 까닭을 한 줄 적는다.

| 학교급 | 주기 |
|---|---|
| 초등 | 1~2개 |
| 중학교 | 2개 |
| 고등학교 | 2~3개 |

**교사가 슬라이드 수를 말했으면** 표지부터 정답 장까지 파일 전체 장 수로 맞춘다. `make_deck.py`는 `check`, `task`, `example` 뒤에 정답 장을 저절로 붙이므로 정답 장도 함께 센다. 넘치면 주기 수(또는 주기마다 확인·연습 수)를 먼저 줄이고, 정답 장은 빼지 않는다. 구성표에는 정답 장 수를 따로 적는다.

차시 시간은 교사가 말한 값을 쓰고, 없으면 `references/school-levels.md`를 따른다. 노트의 시간 합이 차시 시간 안에 들게 한다.

### 장 역할별 규칙

| 역할 | 글 | 도식 | 핵심 띠 |
|---|---|---|---|
| 핵심어 | 낱말 3~5개와 짧은 뜻. 새 용어가 없으면 뺀다 | 표나 낱말 칸 | 없음 |
| 수업 안내 | 주기 이름을 질문이나 구로 쓰고, 지금 주기만 드러낸다. 주기마다 같은 틀 | 없음 | 없음 |
| 설명 | 메시지 하나, 짧은 구. 제목은 그 장의 결론이나 질문 | 내용의 구조를 도식으로 | 있음 |
| 확인 | 문항 하나, 1분 안에 답할 수준. 문장을 써도 된다 | 없어도 된다 | 없음 |
| 연습 | 학생이 2~5분 쓰거나 말하는 과제. 지시문은 문장으로, 번호를 붙이고 시간과 산출물을 적는다 | 없어도 된다 | 없음 |
| 답 | 연습·확인 장과 같은 틀에 답만 얹는다. 답은 강조색과 굵기로 가른다 | 문제 장과 같다 | 없음 |
| 활동 | 이름 장 + 방법 장. 방법 장에 시간, 역할, 산출물, 준비물을 쓴다. 방법이 5줄을 넘으면 학습지로 보내고 답변에 적는다 | 없어도 된다 | 없음 |
| 요약 | 차시 전체를 2~3문장으로. 지도안에 탐구 질문이 있으면 그 질문에 답하고, 없으면 학습 목표와 짝을 맞춘다 | 없음 | 없음 |

- **확인 문항의 유형을 섞는다**: 하나 고르기, 참·거짓 + 근거 고르기, 틀린 말 찾기, 잇기. 내용에 맞게 고른다.
- **답이 하나가 아니면** "이렇게 쓸 수 있어요"처럼 예시임을 밝힌다. 객관식은 왜 틀렸는지도 화면이나 노트에 적는다.
- **산출물 과제**에는 다른 소재의 예시 산출물을 함께 보여 줄 수 있다.
- 기기가 없을 때의 대체 방법을 노트에 적는다.

### 체계적으로 나누는 기준

- **한 장에 메시지 하나.** 제목은 그 장의 핵심을 말하는 문장이나 구로 쓴다. 예: "입자는 스스로 움직인다"
- **설명 장의 항목은 3~5개**, 한 항목은 한 줄 안팎. 설명이 길면 하위 항목(`sub`)으로 나눈다.
- **두 개념을 견주면 `compare`**, **세 개 이상 속성을 견주면 `table`**을 쓴다.
- **순서가 있는 절차**(실험, 풀이)는 번호가 드러나는 단계나 표로 쓴다.
- 강조는 `**굵게**`로 핵심어에만 쓴다 (한 장에 1~3개). 글자에 별표가 남으면 안 된다.
- 내용이 넘치면 나눈다. 생성기가 "(계속)"을 붙여 잇거나 경고를 낸다 (4절). 나뉘었다면 내용을 줄일 수 있는지 먼저 검토한다.
- 관련된 정보는 한 장에 모은다. 쪼개기만 하면 학생이 앞 장을 기억해야 한다.

### 시각화 (글만 나열하지 않기)

**설명 장은** 글 줄만 늘어놓지 않는다. 내용의 구조를 먼저 정하고, 그 구조에 맞는 도식으로 보여 준다. 다만 그림은 정보를 담을 때만 쓴다. 넣을 도식이 없으면 큰 문장 하나가 장식 그림보다 낫다. 확인·연습·답 장은 문제와 지시를 문장으로 쓴다. 패턴별 만드는 법, 핵심 포인트 띠, 줄바꿈·정렬 규칙은 `references/visual-design.md`를 따른다.

| 내용의 구조 | 시각화 |
|---|---|
| 시간 순서 (사건, 단계) | 연표: 선 위에 연도 원 + 아래 짧은 설명 |
| 원인 → 결과, 과정 | 흐름: 갈매기형(chevron)·화살표로 이은 카드 |
| 두 대상 비교 | 좌우 카드 (가운데 vs) |
| 세 개 이상 요소 | 아이콘·번호 카드 격자 |
| 핵심 수치·연도 | 큰 숫자를 원이나 띠에 강조 |
| 장소·이동 | 지도나 사진 + 짧은 캡션 |
| 움직임이 핵심인 현상 (입자 운동, 열 이동, 파동, 천체 운동, 개체 수 변화) | 실시간 시뮬레이션 (앱 슬라이드, `references/app-slides.md` 4절). 생성기로 만들 때는 처음·조금 뒤·나중 세 칸 그림 |

- 설명 장마다 **핵심 포인트 하나**를 정해 "핵심: …" 띠 한 줄로 보여 준다 (표지·목차·핵심어·확인·연습·답·마무리 제외). 앱 슬라이드는 `.key`(노란 '핵심' 칩 + 한 줄)가 이 띠다.
- 설명 장의 카드 글은 **2줄 이내**. 제목어(굵게) 한 줄 + 설명 한 줄이 기본이다.
- 설명 장에 3줄 넘는 글머리표 목록이 생기면 카드나 연표로 쪼갠다. 자세한 설명은 발표자 노트로 옮긴다.
- 한 줄 분량의 글이 몇 글자만 다음 줄로 꺾이지 않게 상자를 넓히거나 글을 다듬는다.
- 사진·그림·글·상자·선 등 모든 도형은 슬라이드 테두리 안에 둔다. 양식 그림이 잘려 있어도 줄이거나 옮겨 안으로 넣는다.
- (pptx 생성기·양식 복제 기준) 글자는 가로·세로 가운데로 맞춘다. 표 안 글자와 지시문도 같다. 교사 양식이 있으면 양식의 정렬이 우선이다. 앱 슬라이드는 이 줄을 따르지 않고 `references/house-style.md` 4절을 따른다.
- 사건의 전개처럼 내용이 많은 부분은 개요 장(예: 단계 지도 한 장) 뒤에 단계별 상세 장(지도 + 날짜별 연표 + 현장 사진 + 핵심 띠)으로 펼친다.
- 색은 양식(테마)의 색을 따르고, 강조색은 한두 가지만 쓴다.
- 답은 색만으로 가르지 않는다. 굵기나 표시를 함께 쓴다.

### 학교급별

| 학교급 | 기준 |
|---|---|
| 초등 | 쉬운 말, 항목 3개 이하, 그림 자리 많이, 활동 단계 짧게 |
| 중학교 | 개념 → 예시 → 확인 흐름, 비교·표 활용 |
| 고등학교 | 자료 해석, 개념 간 관계, 표와 도식 비중 높임 |

### 교과별

뼈대의 후보다. 지도안이 있으면 지도안을 따른다. 어떤 교과든 설명 → 확인 → 연습 → 답의 자리는 남긴다.

| 교과 | 뼈대 | 주의 |
|---|---|---|
| 국어 | 예문 → 문장 표지 → 짧게 고치기 → 문단 고쳐 쓰기 → 자기 점검 | 긴 지문은 학습지로 보내고 화면에는 근거 문장만 띄운다. 작품 전문은 교사가 준 범위만 쓴다 |
| 영어 | 소리·낱말 입력 → 듣고 따라 하기 → 연결·표 채우기 → 그림 단서 말하기 | 뒤로 갈수록 학생 산출을 늘린다. 듣기 자료는 지어내지 않고 자리만 표시한다. 지시문 언어는 교사에게 맡긴다 |
| 수학 | 표상 → 예제와 문제의 짝 → 확인 → 연습과 답 | 왼쪽에 풀이, 오른쪽에 같은 구조의 문제를 둔다. 수식은 그림이 아닌 고칠 수 있는 글로 쓴다 |
| 사회 | 상황 → 해결 가능한 질문 → 자료 읽기 → 입장 비교 → 제안 | 논쟁 주제는 입장을 고르게 싣고 어느 편도 들지 않는다. 지역 자료는 받은 것만 쓴다 |
| 과학 | 예측 → 관찰 → 설명, 또는 방법 → 결과표 → 결론 문장 틀 | 실험 장에 준비물, 대체 도구, 안전 주의를 둔다. 결과 값을 지어내지 않고, 예시 표는 "예시"라고 적는다 |

### 발표자 노트

모든 주요 슬라이드에 `notes`를 넣는다: **말할 내용(발문이나 설명 대본), 예상 답과 흔한 오해, 시간(분), 출처.** 확인·연습 장에는 답과 다음 행동을 함께 적는다. 예: "절반 넘게 틀리면 앞 설명으로 돌아간다." 화면에서 뺀 설명은 노트로 옮긴다. 지도안이 있으면 지도안의 발문을 그대로 옮긴다.

## 3. 자료와 그림

- **교사가 준 PDF와 자료는 수업용이므로 그대로 가져다 쓴다.** 본문, 표, 핵심 문장을 옮겨 쓰고 슬라이드에 출처 쪽(예: "교과서 32쪽")을 `caption`이나 노트에 적는다.
- 교사가 준 자료에 그림이 있으면 그림 파일로 추출해 `figure`의 `image`에 넣는다 (코드 실행 환경에서 PDF 이미지를 추출할 수 있을 때). 추출이 안 되면 `[그림: 교과서 32쪽 입자 모형]`처럼 자리를 표시한다.
- **인터넷 자료는 교사가 원한다고 했을 때만 찾는다** (1절의 인터넷 자료 질문에 필요하다고 답했을 때 포함). 수업 자료, 통계, 사진, 지도를 찾을 수 있다. 질문 없이 진행할 때는 찾지 않고 받은 자료로만 만든다.
- 이미지는 **퍼블릭 도메인이나 CC 라이선스**(예: 위키미디어 공용)만 쓰고, 이미지마다 출처와 라이선스를 발표자 노트에 적는다. 저작권이 불분명한 이미지는 쓰지 않는다. 파일은 png나 jpg로 저장해 넣는다.
- 인터넷에서 찾은 글과 통계는 출처를 슬라이드나 노트에 적는다. 출처를 확인할 수 없는 값은 쓰지 않고 `[확인 필요]`로 둔다.
- 인터넷 검색을 쓸 수 없으면 `[그림: …]` 자리만 남기고 그 사실을 답변에 알린다.
- 영상은 슬라이드에 넣지 않고 제안만 한다. 제목, 출처, 쓸 구간을 노트와 답변에 적고, 주소는 검색으로 확인한 것만 쓴다. 지어내지 않는다.
- 역사적 사건·실존 인물을 꾸며 낸 그림(AI가 만든 "사진")은 쓰지 않는다. 사실처럼 보여 학생을 오도한다. 도식(연표, 흐름도, 카드)은 도형으로 직접 그린다.
- 그 밖에는 그림을 새로 그리거나 인터넷에서 가져오지 않는다.
- 지역 자료, 통계, 날짜는 받은 자료나 교사가 원해서 찾은 자료에 있는 것만 쓰고, 없으면 `[확인 필요]`로 둔다.
- 학생 산출물 사진은 교사가 준 것만, 이름과 얼굴을 가린 뒤 쓴다.

## 4. 파일 만들기

### 만드는 방법 고르기

| 상황 | 방법 |
|---|---|
| 교사가 예시 슬라이드가 든 양식(.pptx)을 줬다 (Canva 양식 등) | 아래 `fill_template.py`로 **양식 슬라이드를 복제해 채운다.** 새로 디자인하지 않는다. |
| 교사가 슬라이드 없이 마스터·레이아웃만 있는 템플릿을 줬다 | `make_pptx.py`에 `"template"`을 넣어 만든다. |
| 교사가 테마 이름(기본, 초등, 이과, 문과, 고대비)을 먼저 말했다 | `make_pptx.py`로 그 테마를 쓴다. |
| 템플릿이 없고, 환경에 클로드 앱의 슬라이드 기능이 있다 (claude.ai) | **앱 슬라이드로 만든다 (기본).** `references/app-slides.md`, `references/house-style.md`, `references/app-deck-example.md`를 따른다. 화면에서 바로 고치고 발표하며, .pptx나 PDF로 내려받을 수 있다. |
| 그 밖 (Claude Code 등, 앱 슬라이드 기능이 없음) | `make_deck.py`로 만든다. 입력 장 종류는 스크립트 상단 설명을 따른다. |

어느 방법이든 **2절 내용 구성 기준**(주기, 장 역할별 규칙, 발표자 노트)과 **5절 출력**을 그대로 따른다. 아래 "장 역할과 입력 종류"부터는 생성기를 쓸 때의 설명이다.

### 장 역할과 입력 종류

| 역할 | `make_deck.py` | `make_pptx.py` |
|---|---|---|
| 표지, 학습 목표, 요약 | `cover`, `goals`, `summary` | 같음 |
| 핵심어 | `keywords` | `table` |
| 수업 안내 | `outline` (`current`로 지금 위치) | `content` (지금 주기를 `**굵게**`) |
| 소주제 표지, 활동 이름 장, 차시 예고 | `section` | 같음 |
| 설명 | `content`, `flow`, `cards`, `compare`, `table`, `figure` (모두 `key`로 핵심 띠) | 같음 (`flow`, `cards`, `figure`의 `callouts` 포함) |
| 확인 | `check` (`quiz`와 같음. `truth`, `reasons`로 참·거짓 + 근거) | `quiz` |
| 연습과 답 | `task` | `content` 두 장 |
| 예제와 문제의 짝 | `example` | `compare` |
| 활동 방법 장 | `activity` | 같음 |

- **답 장**: `make_deck.py`는 `check`, `task`, `example` 뒤에 답 장을 저절로 붙이고 노트에 답을 넣는다. 답 장을 빼려면 `"reveal": false`를 쓴다. `make_pptx.py`는 `quiz`에 `"reveal": true`를 넣을 때만 답 장을 만들고, 그 장의 노트에 정답과 다음 행동(`reveal_notes`, 없으면 기본 문구)을 넣는다.
- **make_pptx.py에 없는 장**: `keywords`, `outline`, `check`, `task`, `example`은 `make_pptx.py`에서 쓸 수 없다. 쓰면 오류 문구가 위 표의 대체 장(`table`, `content`, `quiz`, `content` 두 장, `compare`)을 알려 주니, 그 장으로 바꿔 다시 만든다. 템플릿 경로에서는 확인·연습·답 장의 노트에 답을 직접 적는다.
- **넘칠 때**: `make_pptx.py`는 다음 장에 이어 쓴다. `make_deck.py`는 `content`의 항목이 5개를 넘거나 한 장에 담으면 글자가 20pt보다 작아질 때 "(계속)"으로 잇는다. 행 높이는 줄 수에 비례해 나누므로 하위 항목이 많은 행 하나 때문에 다른 행이 작아지지 않는다. 그래도 18pt(교실 기준)보다 작아지면 경고한다.

### make_deck.py

```bash
python scripts/make_deck.py 슬라이드.json 수업.pptx
```

- 그림 경로는 입력 JSON이 있는 폴더를 기준으로 찾는다. 그림이 없으면 `[그림: …]` 자리를 만든다.
- "확인 필요" 경고가 나오면 해당 장의 글을 줄이거나 나눈 뒤 다시 만든다. 노트가 빠진 장도 알려 준다.
- 수업 안내(`outline`)가 있으면 주기마다 `current`를 바꾼 안내 장이 있는지 검사하고, 빠진 주기를 "전체: 수업 안내 장이 없는 주기가 있음"으로 알려 준다. 안내 장 없이 `section`이 2개 이상일 때도 알려 준다.
- "끝 줄에 몇 글자만 남음", "넘칠 수 있음" 경고가 남으면 글을 다듬거나 나눠 다시 만들고, 경고가 없어진 뒤에 넘긴다.
- PowerPoint와 한쇼에서 열린다고 안내한다.
- 교사가 학생에게 나눠 줄 파일을 원하면(1절 4번 질문에 그렇다고 답했거나 따로 요청했으면) 같은 입력에 `--student`를 붙여 다시 만든다: `python scripts/make_deck.py 슬라이드.json 학생용.pptx --student`. 답 장을 만들지 않고 발표자 노트를 모두 비운다(노트에 정답이 있다).

### make_pptx.py

```bash
python scripts/make_pptx.py 슬라이드.json 수업.pptx
```

- 교사 템플릿이 있으면 `"template": "템플릿.pptx"`를 넣는다. 템플릿의 배경과 디자인을 그대로 두고 내용만 채운다. 강조색은 템플릿 테마의 색(accent1부터, 배경 위에서 보이는 것)을 읽어 쓰고, 읽지 못할 때만 `theme`의 색을 쓴다. 쪽 번호는 템플릿의 띠 같은 바탕에 맞춰 색과 자리를 고른다.
- 설명 장(`content`, `flow`, `cards`, `compare`, `table`, `figure`)에는 2절 기준대로 `key`를 넣어 핵심 띠를 만든다. 글은 `make_deck.py`와 같이 가운데 정렬이다. 템플릿 제목 자리는 템플릿의 정렬을 따른다.
- "확인 필요" 경고가 나오면 해당 슬라이드를 줄이거나 나눈 뒤 다시 만들고, 경고가 없어진 뒤에 넘긴다.
- PowerPoint와 한쇼에서 열린다고 안내한다.
- 학생용 사본도 `--student`로 만든다: `python scripts/make_pptx.py 슬라이드.json 학생용.pptx --student` (`quiz`의 정답 장과 발표자 노트를 뺀다. 같은 입력이면 `make_deck.py`와 같은 동작이다).

### fill_template.py (교사 양식 복제)

양식의 디자인(배경, 장식, 배치, 글꼴, 색)은 그대로 두고 글과 사진, 인포그래픽 도형만 바꾼다. 양식에 있던 원래 글과 주제에 맞지 않는 사진은 하나도 남기지 않는다.

1. **양식 살펴보기**: `python scripts/fill_template.py --inspect 양식.pptx`로 장마다 도형 이름, 위치(EMU), 글자 크기, 글을 확인한다. PowerPoint나 LibreOffice가 있으면 양식을 그림으로 내보내 디자인도 눈으로 본다.
2. **장 고르기**: 수업 흐름(2절)의 각 장에 맞는 양식 장을 고른다 (표지→표지, 목차→수업 안내, 카드 3개→세 요소, 사진 장→사진 자료 등). 같은 양식 장을 여러 번 써도 되고, 연습과 답은 같은 양식 장을 두 번 쓴다.
3. **채우기**: JSON의 `text`로 글을, `images`로 사진을 바꾸고, 쓰지 않는 도형은 `remove`, 칸이 모자라면 `clone`, 글자가 작으면 `size`, 자리를 옮기려면 `geometry`를 쓴다. 글만 나열될 설명 장은 `add`로 연표·흐름·카드를 그린다 (2절 시각화).
4. **만들기**: `python scripts/fill_template.py 입력.json 수업.pptx`
5. **확인하기**: `references/visual-design.md` 8절의 절차를 따른다. "확인 필요" 경고(넘침, 몇 글자만 다음 줄로 넘어감)를 모두 고치고, Windows + PowerPoint가 있으면 `scripts/render_slides.ps1`로 모든 장을 그림으로 보고 `scripts/check_wrap.ps1`로 실제 줄바꿈을 센다. 실측 0건, 겹침 0건이 될 때까지 고쳐 다시 만든다. 마지막 점검표를 통과한 뒤에 넘긴다.

`fill_template.py`에는 `--student`가 없다. 학생용 사본을 원하면 입력 JSON에서 정답이 든 장과 `notes`를 빼고 다시 만든다.

양식 슬라이드가 20인치 폭처럼 크면 양식의 18pt 본문도 화면에서는 작게 보인다. 카드 본문은 20~24pt를 기본으로 한다.
