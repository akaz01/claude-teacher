# 클로드 앱 슬라이드로 만들기 (기본 방법)

**쓰는 때**: 교사가 PPT 템플릿을 주지 않았고, 지금 환경에 클로드 앱의 슬라이드(Slides) 기능이 있을 때 (claude.ai 등). 이때는 이 방법이 기본이다. 생성기(`make_deck.py`)와 JSON은 쓰지 않는다.

**스타일은 고정이다.** `house-style.md`의 색·글꼴·크기와 `app-deck-example.md`의 `deck.css`를 그대로 쓴다. 덱마다 새 색이나 글꼴을 정하지 않는다. 디자인 시스템은 "teacher-kit 수업 디자인"만 설치한다(`design-system-setup.md`). 다른 디자인 시스템은 교사가 말하지 않았으면 쓰지 않는다.

앱 슬라이드 기능의 자체 안내(파일 구조, 올리는 방법, 형식 제한)는 따른다. 내용은 SKILL.md 2절, 모양은 이 파일과 `house-style.md`가 우선이다.

## 1. 순서

0. `design-system-setup.md`대로 교사 계정의 디자인 시스템 "teacher-kit 수업 디자인"을 준비한다(없으면 만들고, 판이 낮으면 올린다). 덱을 만들 때 이것을 설치한다.
1. SKILL.md 2절에 따라 구성표(번호, 역할, 제목, 핵심 내용)를 먼저 정한다. 이때 장마다 아래 2절의 어떤 마크업을 쓸지, 시뮬레이션과 클릭 공개를 어디에 쓸지도 정한다.
2. 앱 슬라이드로 덱을 만든다. 덱 제목: "교과 학년 – 차시 주제". 예: "과학 1학년 – 입자는 스스로 움직일까?"
3. `project/deck.json`, `project/deck.css`(예시 그대로), 표지를 먼저 올리고, 나머지 장을 순서대로 올린다.
4. 시뮬레이션이 있는 장, 손으로 자리를 잡은 장은 앱 안내의 미리보기 절차로 확인한다. 글이 넘치거나 겹치면 글을 줄이거나 장을 나눈다(글자를 줄이지 않는다).
5. 6절 출력대로 답한다.

## 2. 장 역할별 마크업

모두 `app-deck-example.md`에 실제 코드가 있다. 클래스와 구조를 그대로 쓰고 글만 바꾼다.

| 역할 | 바탕 (`section` 클래스) | 마크업 | 예시 |
|---|---|---|---|
| 표지 | `cover` | 왼쪽 `.cv-l`(점 무늬 `.cv-dots` + `.cv-chip` 교과·학년·단원·차시 + `.display` 명조 제목 + `.cv-bar` + `.lead` 부제) / 오른쪽 `.cv-r`(주제 선 그림 SVG) | `cover` |
| 학습 목표 | (기본) | `.head` + `.list`의 `.li`(큰 명조 번호 `.li-n` + `.li-t`) | `goals` |
| 핵심어 | (기본) | `.stack` 안에 `.cols` 두 줄(두 번째에 `rowsep`), 뜻 `.c-t`에 `fragment` | `keywords` |
| 수업 안내 | (기본) | `.list`, 지금 주기만 진하게 + `.now` 칩, 나머지 `.li-off` | `guide1` |

| 활동 | `dark` | 연습 장 틀(`.prac` + `.cards`) | `task1` |

- 표지를 뺀 모든 장은 `.top`(왼쪽 머리말 칩 `.eyebrow` + 오른쪽 과목 줄 `.course`)으로 시작하고, 흐름 요소 맨 끝(`x-embed` 앞)에 진행 막대 `.foot`를 둔다. `.foot`의 채움 너비는 (장 번호 ÷ 전체 장 수), 글은 "05 / 17"처럼 쓴다. `.head`는 `.top` + `.ttl` 제목이다.
- 머리말 칩(`.eyebrow`)에는 위치를 쓴다: "주기 1 · 확산", "확인 1 · 하나 고르기", "연습 1 · 혼자 쓰고 짝과 비교". 과목 줄은 "과학 1 · 물질의 상태 변화"처럼 덱 전체가 같다.
- 장 제목은 결론 문장이나 질문으로 쓴다(SKILL.md 2절). 명조, 왼쪽 정렬이다.
- 설명 장은 맨 아래에 `.key`(노란 '핵심' 칩 + 한 줄)를 둔다. 확인·연습·답·요약 장에는 두지 않는다.
- 확인 문제 보기가 짧으면(수식, 낱말, 수치) `.opts`를 두 칸(`style="display:grid;grid-template-columns:1fr 1fr"`)으로, 길면 한 줄에 하나로 둔다.
- 핵심어 낱말이 3개면 `.cols` 한 줄에 칸 3개, 4개면 예시의 2×2(`.cols` 두 줄, 두 번째 줄에 `rowsep`), 5개면 위 줄 3칸 + 아래 줄 2칸으로 둔다. 칸 마크업(`.c`, `.c-word`, `.c-t fragment`)은 그대로 쓰고 칸 수만 바꾼다.
- 표지의 오른쪽 그림은 차시 주제를 담은 선 그림(SVG)을 새로 그린다: 남색 선 + 파랑·노랑 점 정도, 600×600 안팎. 수학은 그래프, 과학은 현상 모형, 사회는 도식, 국어·영어는 핵심 낱말을 크게. 움직이는 배경(`x-embed`)은 표지에 쓰지 않는다.
- 같은 역할의 장은 같은 마크업을 쓴다. 장마다 다른 배치를 새로 만들지 않는다.

## 3. 클릭 공개 (fragment)

발표 중 클릭하면 나타나는 요소다. 학생이 먼저 생각하게 한 뒤 보여 줄 때 쓴다.

- **확인 문제의 정답**: 한 장에 문항과 보기를 두고, 정답과 까닭은 `.reveal.fragment` 띠로 숨긴다. 그래서 확인 문제는 정답 장을 따로 만들지 않는다.
- **핵심어의 뜻**: 낱말만 보이게 하고 뜻을 하나씩 공개한다.
- **연습 답**: 시뮬레이션으로 직접 본 뒤 예시 답을 공개한다. 글로만 된 연습 답은 다음 장(`.answer`)에 둔다.
- 노트에 "클릭하면 정답이 나타난다"와 클릭 횟수를 적는다.
- 숨긴 답도 링크와 내려받은 파일에 들어 있고, 내려받은 pptx·PDF에서는 처음부터 보일 수 있다. 6절 3·4번 안내로 알린다.

## 4. 실시간 시뮬레이션 (x-embed)

눈에 보이지 않거나 시간이 걸리는 현상을 화면에서 움직여 보여 준다. 슬라이드 안에서 작은 프로그램이 돌아간다.

**쓰는 때**: 입자의 운동(확산, 증발, 상태 변화, 기체 압력), 열의 이동, 파동, 전류, 천체의 운동, 생태계 개체 수 변화, 확률 실험처럼 "움직임"이 개념의 핵심일 때. 차시에 1~3개. 정적인 구조(분류, 비교, 절차)는 도식으로 그린다.

**규칙**
- 개념을 흉내 낸 그림이다. 실제 측정값처럼 숫자를 보여 주지 않는다. 노트에 "모형으로 흉내 낸 것"이라고 적는다.
- 자리: 제목 아래 본문 칸 전체. `position:absolute; left:128px; top:300px; width:1664px; height:420px`(설명 한 줄 + 핵심 줄이 있을 때). 연습 답처럼 아래에 정답 띠 하나만 있으면 높이 500px. 제목이 두 줄이면 제목을 줄이거나 장을 나눈다.
- `<x-embed>`는 `<section>`의 바로 아래 자식으로, 흐름 요소들 뒤·`<aside>` 앞에 둔다.
- 캔버스 하나로 그린다. 16KB 이하. 바깥 글꼴이 들어가지 않으므로 글자는 `"Malgun Gothic","Apple SD Gothic Neo",sans-serif` 30px 굵게.
- 하우스 색만 쓴다: 흰 바탕 `#FFFFFF`에 모서리 28px, 테두리 `#CBD3DD` 2px, 입자 파랑 `#2E6DB4`(두 번째 물질은 보라 `#5B3FA6`), 물 `#CFE0F2`, 찬물·더운물 칸은 `#E3EEF8`·`#FBE6D6`.
- 학생이 클릭하거나 입력할 수 없다. 12~30초마다 처음부터 다시 돌고, 오른쪽 위에 "지난 시간 n초"를 보인다.
- 예시의 공통 코드(`fit`, `rr`, `mk`, `move`, `dot`, `label`)를 그대로 쓰고, 장면 부분만 새로 쓴다. 입자는 속도와 방향을 가지고 가끔 방향을 바꾸는 방식(`move`)으로 움직인다. 제자리에서 떨기만 하면 퍼지지 않는다.
- 온도처럼 비교하는 장면은 두 칸을 나란히 두고 조건만 다르게 한다(예: 속도 1.1과 4.2).
- 내려받은 pptx·PDF에서는 시뮬레이션이 움직이지 않고 멈춘 그림이나 안내 글만 남을 수 있다(6절 3번과 같은 설명). 그래서 시뮬레이션은 앱 발표 화면에서 보여 주는 용도로 쓴다.

## 5. 노트와 그림

- **발표자 노트**: 모든 장에 `<aside>`로 SKILL.md 2절의 노트(말할 내용, 예상 답과 흔한 오해, 시간, 출처)를 넣는다. 시뮬레이션 장에는 무엇을 보게 할지와 실제 실험·시연 대안을, 클릭 공개 장에는 클릭 순서를 적는다. 한 장에 4,000자 이하.
- 노트와 정답(클릭 공개, 연습 답 장)은 링크를 가진 사람과 내려받은 파일을 받은 사람이 볼 수 있다. 학생에게 줄 파일은 7절의 학생용 사본으로 만든다.
- 교사가 준 교과서·자료의 그림은 png로 뽑아 앱에 올린 뒤 넣는다. 올릴 수 없으면 빈 그림 자리와 `[그림: 교과서 32쪽 입자 모형]` 글을 두고 출력에 적는다.
- 인터넷 그림은 SKILL.md 3절 규칙 그대로다.

## 6. 출력에 더할 것

SKILL.md 5절 출력에서 "만든 파일" 자리에 아래를 쓴다.

1. 슬라이드 링크
2. 쓰는 법 한 줄: "발표 화면에서 시뮬레이션이 움직이고, 클릭하면 정답이 나타납니다."
3. 내려받기 안내 한 줄: "공유 › 내보내기에서 PowerPoint(.pptx)나 PDF로 내려받을 수 있습니다. 내려받은 파일에서는 시뮬레이션이 움직이지 않고 멈춘 그림이나 안내 글만 남을 수 있으며, 클릭해야 나오는 답이 처음부터 보일 수 있습니다."
4. 정답 안내 한 줄: "링크와 내려받은 파일에는 정답(클릭해야 나오는 답, 연습 답 장, 발표자 노트)이 들어 있습니다. 학생에게 나눠 줄 파일이 필요하면 말씀해 주세요. 정답을 뺀 학생용 사본을 만들어 드립니다."
5. 고치는 법 한 줄: "글자는 화면에서 바로 고치실 수 있고, '5번 장을 쉽게'처럼 말씀하셔도 고쳐 드립니다."

## 7. 학생용 사본 만들기 (SKILL.md 1절 4번 질문에 "학생에게 나눠 줄 파일"이라고 답했거나 교사가 따로 요청했을 때)

Claude가 따르는 내부 절차다. 원본 덱은 그대로 두고 복제한 사본에서만 고친다.

1. 덱을 복제하고 제목 끝에 "(학생용)"을 붙인다.
2. 모든 `.reveal.fragment`(확인 문제 정답 띠, 연습 예시 답 띠)를 지운다.
3. 핵심어의 뜻 `.c-t.fragment`는 글을 비운다(낱말만 남긴다).
4. 연습 답 장(`task1ans`, `task2ans`처럼 답을 보이는 장)을 사본에서 뺀다. `deck.json`의 `order`와 `sections`의 `start`에서도 빼고, 남은 장마다 `.foot`의 채움 너비와 "05 / 17"을 다시 센다.
5. 모든 장의 `<aside>`(발표자 노트) 글을 비운다.
6. 마무리 점검: 사본의 모든 장에서 `reveal`, `fragment`, `<aside>` 안의 글, '정답'·'예시 답' 글자가 남지 않았는지 훑는다. 시뮬레이션 장은 답을 보이지 않으므로 그대로 둔다.
7. 사본을 공유 › 내보내기에서 PDF로 내려받게 안내한다.
