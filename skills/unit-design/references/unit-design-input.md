# 단원 설계서 입력 (make_unit_design.py)

SKILL.md 7절에서 학교 양식이 없을 때 쓴다. 실행: `python scripts/make_unit_design.py 단원설계.json 단원설계.hwpx`

## 칸과 입력 이름

| 설계서 칸 | 입력 | 쓰는 법 |
|---|---|---|
| 머리 정보 | `info` | `subject`, `grade`, `unit`, `periods`(숫자), `curriculum`, `date`(YYYY-MM-DD), `semester_periods`(한 학기 차시 기준 글) |
| 성취기준 분석 | `stage1.standards` | 성취기준마다 `code`, `text`(원문), `know`(알아야 할 것), `do`(할 수 있어야 할 것) |
| 핵심 아이디어 | `stage1.core_ideas` | 고시문 문장 그대로 (`references/curriculum/core-ideas/`) |
| 내용 요소 | `stage1.content_elements` | `지식⋅이해`, `과정⋅기능`, `가치⋅태도`마다 목록. 고시문 그대로 |
| 핵심 개념 | `stage1.concepts` | 2~4개 |
| 영속적 이해 (일반화) | `stage1.understandings` | 1~3문장 |
| 핵심 질문 | `stage1.essential_questions` | 1~2개. 답이 영속적 이해가 되는 질문 |
| 탐구 질문 | `stage1.questions` | `사실`, `개념`, `논쟁`마다 목록 |
| GRASPS 수행과제 | `stage2.grasps` | `goal`, `role`, `audience`, `situation`, `product`, `standards`. 빈칸은 `[확인 필요]`로 찍히고 경고가 난다 |
| 채점 기준 요약 (선택) | `stage2.criteria` | `element`(평가 요소), `look`(보는 것). 점수는 쓰지 않는다 |
| 평가 배치 | `stage2.evidence` | `periods`(차시 또는 "정기시험"), `kind`(진단·형성·수행·지필), `method`, `focus`(확인할 것), `standards`(코드 목록) |
| 차시별 흐름 | `stage3` | 차시마다 `periods`, `goal`, `activities`, `assessment`, `standards`(코드 목록) |
| 다음 단계 | `next_steps` | `skill`, `request`(교사가 그대로 보낼 문장), `what`(넘길 내용) |

- 글 안 줄바꿈은 `\n`이다. 목록으로 준 값은 한 칸 안에서 줄마다 나뉜다.
- `standards`(코드 목록)는 일체화 점검에 쓰인다. 차시와 평가에 빠짐없이 적는다. 생성기가 "다루는 차시가 없음", "평가 증거가 없음", "배우기 전에 있음", "1단계에 없는 성취기준", "차시 수가 맞지 않음"을 "점검:" 줄로 알린다.
- 생성기는 작성일이 YYYY-MM-DD가 아니면 만들지 않는다.
